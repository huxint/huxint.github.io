## 通用处理

- 删除了全部动画：`<animate>` / `<animateTransform>` / `<animateMotion>`，以及仅靠动画才可见的元素（流动的数据点、扫光高亮、广播脉冲环、闪烁指示灯、旋转虚线环改为静止）。
- 互斥的两套图层（如队友卡片上的「运行中 / 待命」药丸、运行态描边）各只保留一种静态状态：planner 运行中、critic 待命、tester 运行中、coder 待命。顶部「队友状态」图例保留两枚药丸，仅去掉闪烁。
- 保留 `<title>` / `<desc>`（含 id）与 `role="img"`；`<desc>` 中涉及修订的措辞同步更新。
- 布局、配色、方框、箭头与其余文字均未改动。

## 文字修订

### architecture-overview.svg

| 修订前 | 修订后 | 原因 |
|---|---|---|
| HTTP 接口 + SSE 事件流，浏览器里对话 | HTTP chat 接口与 SSE 事件流 | Web 服务只提供 HTTP chat 接口与 SSE 事件流；`web/` 下的前端仅是设计稿，不应描述为可用的浏览器界面。 |
| 会话 · 记忆 · 定时任务 · 信箱 · 团队 —— 进程重启后接着用 | 会话 · 记忆 · 自动化调度 · 信箱 · 团队元数据 | 信箱库与团队库在 bootstrap 时打开，但持久化的是团队元数据；活跃运行不落库，「重启后接着用」对团队运行不成立。 |
| 注册 \| 一处登记，模型即可见 | 注册 \| 一处登记，定义按需提供给模型 | 工具定义通过 deferred discovery 按需提供给模型，并非注册即全部可见。 |
| 每轮重新组装：系统提示 + 技能 + 工具 + 记忆 | 每轮重新组装：系统提示 + 技能 + 工具；记忆循环前召回一次 | `src/agent/agent-loop.cpp` 中记忆在循环开始前召回一次、每轮复用，不是每轮重新召回。 |
| （desc）状态统一落在 SQLite。 | （desc）会话、记忆、自动化调度、信箱与团队元数据落在 SQLite。 | 与状态层文字保持一致，避免暗示运行状态也落库。 |

### multi-agent.svg

| 修订前 | 修订后 | 原因 |
|---|---|---|
| run、信箱、团队关系都在 SQLite，重启后队还是那支队。 | 信箱与团队元数据持久化；活跃运行保存在内存。 | `src/orchestration/orchestration-manager.cpp` 中 `active_runs` 是内存 map，重启不会恢复运行中的队友。 |
| 待命的队友不占并发槽位；下一条消息把它原地唤醒，上下文接着用。 | 待命的队友不占并发槽位；同进程内下一条消息把它原地唤醒，上下文接着用。 | 待命与唤醒只在同一进程内有效，跨进程重启后没有可唤醒的运行。 |
| 队友手里只有 agent_send_message —— 层级到此为止。 | 队友的编排工具只有 agent_send_message —— 层级到此为止。 | 队友仍有文件、命令行等普通工具，只是编排类工具仅此一个。 |
| （desc）队友手里只有 agent_send_message，所以层级只有两层。 | （desc）队友的编排工具只有 agent_send_message，所以层级只有两层。 | 同上。 |
| （desc）不占并发槽位，下一条消息即可原地唤醒；run、信箱、团队关系全部落在 SQLite。 | （desc）不占并发槽位，同进程内下一条消息即可原地唤醒；信箱与团队元数据持久化，活跃运行保存在内存。 | 同上两条。 |
| 下一条消息把它唤醒，接着上次说 | 同进程内下一条消息把它唤醒，接着上次说 | 与图注、desc 保持一致：待命唤醒只在同一进程内成立。 |

信箱中心的「SQLite 落库」保留：信箱本身确实持久化。
